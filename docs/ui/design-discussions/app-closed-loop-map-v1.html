1. 六頁點樣組成一個完整 MVP 循環

總
總覽頁係導航與待辦中樞，唔係一個線性工序

只讀匯總全局狀態，將 Owner 帶去下一個要處理嘅頁面；唔喺總覽偷偷改策略、數據裁決或交易狀態。

  • 偏離證據、控制、再交 Terminal

結果「用得」

保存不可變決定 → 去模擬盤揀策略、合約同 baseline → 建立新交易員。

結果「打回」或想再傾

匯出 result.v1 → Terminal 分析 → 產生直接衍生新版本 → 返回策略工作台。

結果「放棄」

理由同記分卡快照仍然保存；呢個方向結束，但審計紀錄唔會消失。

4. 閉環接口審計：設計補好咗，但實作仍要逐個驗

based_on_sketch 規格已定；仍要證明 schema、匯入、儲存同 UI 讀取係同一條真實路徑。

B2 · 草圖讀取結果返查 → 策略 → 草圖

前端已有兩種缺失狀態；草圖真寫檔同讀取接口仍待後端交付及實證。

B3 · 結果回流result.v1 → Terminal

位置、包內容、sidecar、失敗狀態已定稿；功能仍未寫。

B4 · 晉升結果 → 模擬盤資格

三個不可變決定、必填理由同記分卡快照已定稿；儲存同接口仍未寫。

B5 · 對照基準baseline run_id 鎖定

Owner 親手揀、唔准自動取最新、建立後鎖死；跟模擬盤一齊實作。

B6 · 偏離回流paper-review.v1 → Terminal

完整不可變 snapshot 已定稿；整個模擬盤子系統未做。

B7 · Owner 已決定A3 唔屬於 MVP

冇盤前計劃、冇市場狀態輸入、冇獨立設定頁；呢個係範圍界線，唔係斷點。

5. 邊啲情況留喺原頁，邊啲情況先向前

留喺原頁處理

  • 策略未驗證／未確認：留喺策略工作台，唔准回測。
  • 數據唔夠或品質裁決未完成：留喺數據頁。
  • 回測 preflight 未全綠：留喺回測頁，唔准建立 run。
  • 結果未有不可變「用得」決定：唔可以建立模擬交易員。
  • 模擬 readiness 任一項未知／失敗：fail-closed，唔啟動。

MVP 刻意唔包括

  • A3 盤前計劃。
  • 獨立市場狀態／策略設定頁。
  • 由 app 直接呼叫 AI。
  • 自動判斷策略「成功」或自動晉升。
  • 自動用最近一次回測做模擬 baseline。

最終確認

如果問「目前設計圖有冇 cover 完整 App？」

有。總覽、策略工作台、數據、回測、結果、模擬盤六頁已足夠形成 MVP；唔需要第七個獨立設定／盤前頁。

如果問「而家個 App 係咪已經由頭到尾真係行得通？」

未係。要等所有黃色／紅色接口完成，再用真 artifact ID、真檔案、真 API 同逆向回流測試逐條證明。

所以正確結論係：設計閉環已完成；工程閉環仍在施工。呢張圖冇新增任何頁面，亦冇改六份權威設計。
