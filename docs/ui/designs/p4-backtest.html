實作約束 mockup 表達唔到嘅決定

#約束理由
1移除「validation_run（工程驗證，非策略主張）」勾選——改為只喺 CLI 用Owner 永遠只做「試策略」；呢個開關係開發者驗證引擎用嘅。Owner 撞到完全唔明
2移除「開啟參數 override」整個功能已被「策略庫撳編輯改參數 → 生成新版本」取代（P2 約束 #18）。新做法有名字、事後查得返，比臨時蓋過好
3時間用本地時間 picker，旁邊同時顯示 UTC 對照P2 約束 #25 同一原則。數據同 session 用 UTC 定義，Owner 要核對得到
4session（rth／eth）顯示但唯讀，由策略文件決定喺呢頁改就會同策略文件唔一致。但同時揀兩個唔同 session 嘅策略時要睇得出
5開始前三個檢查：數據覆蓋 · 暖機不足 · 已跑過相同組合省 Owner 十幾分鐘。「0 交易」有三個可能原因，三個下一步動作完全唔同
6暖機檢查要由已確認策略 ＋ 實際 engine dependencies推算；現行 Trend Daily regime exact 要 95 個 run 前、已收市、合資格原生日線交易日。講明實際可評估日數；不足時只可建議回填更早資料，或將開始日推後暖機只用 run 前歷史，唔准偷睇 run 內／未來 bars。將開始日推早反而減少 warm-up，方向錯；18EMA 變體仍共用 EMA90 Daily regime，唔可錯報 18 日
7「已跑過」檢查比對策略版本 ＋ 合約 ＋ 時間範圍三者全同三者任一唔同就唔算重複
8預覽行用人話：「2 個策略 × 2 個合約 ＝ 4 次回測」＋ 預估時間唔准寫「4 runs」
9進度兩層：總進度條 ＋ 逐個列表（可摺）Owner 拍板。一次跑一兩個時摺埋就夠
10逐個要顯示：測到邊一日、幾筆交易、而家贏輸幾多，正在跑嗰行底色標出Owner 要睇到策略有喺動，唔會懷疑卡住
11🔴 實時進度需要後端改動：引擎要每處理完一個交易日上報一次目前隊列係「跑完才報完成」，中途冇進度。階段 1 用 fixture，階段 2 才接真數據
12取消：只取消未開始嘅，正在跑嗰個跑完已裁決（[086]）。半途殺會留下半寫 artifact，破壞可審計 replay（D19）
13取消掣文案唔准寫「停止」，要寫「取消未開始嘅回測（正在跑嗰個會跑完）」UI 唔准聲稱自己做唔到嘅嘢
14一個失敗唔會拖累其他。失敗要有「看原因」→ 展開完整錯誤原文 ＋ 一鍵複製成純文字（冇 HTML／行號／UI 前綴）。唔准只顯示一句摘要Owner 拍板：會原句貼俾 Agent C 或 terminal AI 睇。同策略庫「複製全部錯誤」同一模式
15歷史列表只夠認得出；「看結果」跳 P5，「再跑一次」用同樣設定重跑（Owner 確認會用）結果分析歸 P5，避免兩頁重複
16🔴 技術詞一律唔准出現喺 UI見下表
17資金與成交假設係第四步，預設收起摘要、可展開調整。只准改初始資金、所選合約手續費同滑點；策略風險／每日上限、保守成交原則同一分鐘精度一律由策略或系統決定並唯讀。多個策略數值唔同時要逐個列明，唔准合併成含糊單值。每個「策略 × 合約」係獨立回測帳戶，各自用完整初始資金起步，唔共同攤分。提交時每次回測都要鎖死資金、成本同成交假設快照；初始資金必須大過 0，成本／滑點不得為負數，滑點只收整數 tick，錯誤要落喺欄位旁並阻止開始。Owner 2026-07-26 拍板方案 A，同時明確確認：4 次回測就係 4 個獨立 USD 100,000 帳戶。快照確保舊結果可重現，之後改預設值亦唔會改寫舊回測
